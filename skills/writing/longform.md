# Long form: articles, essays, blog posts, paper sections

Adapted from mattpocock/skills (`writing-fragments`, `writing-shape`, `writing-beats`), merged into one file.
Two phases, never mixed: **explore** gathers raw material; **exploit** commits to a structure and mines it.
Ask once where each file lives and remember the path. Before every write, re-read the file from disk and keep the
person's edits; append or edit one named block in place, never overwrite the file.

## Explore: fragments
Grill the person about the topic (use the `grilling` rounds) and capture fragments from the first message on.
- A fragment is any text that might survive into the piece and that the author can read: a sharp sentence, a claim
  with one line of reason, a vignette, an example, a half-thought, a quote, a cluster of related notes.
- Most valuable: a **leading word**, one coined term or metaphor the whole piece can hang on. When an idea keeps
  recurring, push to name it.
- File: one H1 working title, then fragments separated by `---`. No headings, tags, metadata or order beyond
  arrival. Append silently and say "adding that"; honour "cut that", "sharper", "merge those two".
- No outlines or structure here: that is exploit's job.

## Exploit: shared rules
Input is the raw pile (fragments, notes, a transcript), read in full first and never edited. Output is a separate
article file.
- **Grounding.** Settle first what the reader already knows (prerequisites). Every other concept must be landed by an
  earlier block before a later block leans on it; land a concept and its name together. Keep a running list of what
  is grounded. Too many prerequisites shut readers out; too much grounding inside drowns the opening.
- **The pile is a quarry.** Split, merge, paraphrase or quote fragments so the piece reads in one voice. When the pile
  lacks something, say so: "we need an example here; give me one or we cut this." Leftover fragments are fine.
- **Push back.** "What does this block do that the last one didn't?" "If I cut it, what breaks?" "This sentence does
  two jobs." "The opening promised X; we drifted to Y."
- **Choose the form of each block out loud:** prose for argument, list for truly parallel items, table when the same
  fields repeat 3+ times, callout only for an aside that would derail the argument, quote when the wording is the point.

Then pick one of two ways to build:

### Shape (structured argument)
1. Draft 2-3 openings, each implying a different thesis; the person picks or blends one.
2. Ask "given this, what does the reader need next?" Fill it from the pile, grounding first if needed.
3. Write each agreed block to the file at once. Repeat until the person says it is done.

### Beats (exploratory path)
1. Offer 2-3 starting beats from the pile; for each, say what it requires and what it grounds.
2. Write only the chosen beat, then offer 2-3 next beats reachable from what is now grounded.
3. A beat does one move (a scene, a point, a question, a twist) and stops; split a beat that needs subheadings.
   End when the journey is complete, not when the pile is empty.

Out of scope: publishing, platform formatting, frontmatter nobody asked for.
